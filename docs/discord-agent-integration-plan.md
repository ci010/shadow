# Discord deep integration and memory-domain authorization

状态：待实现的完整设计方案，不是当前功能说明或安全保证。

日期：2026-10-06。交付方式：一次完成下述闭环，不按 MVP 或分期交付。

## 目标与固定决策

用户不需要知道 Discord ID，即可在 Shadow App 或授权 chat 中发现频道、
分配不同 Agent、编辑指令与工具、理解有效权限，并让这些权限在消息处理、
记忆读取、工具执行、后台任务和重启恢复中一致生效。

- 平台 Bot 身份与 Agent 解耦，默认一个 Bot 服务多个频道，同时支持多个 Bot。
- 复用现有 Project runtime、AgentTypesManager、AGENT.md、SessionManager、
  gateway、VFS 和 Bot instance 模型，不建立 Discord 专用 Agent loop。
- Project 是最外层运行时和数据所有权边界；同一 Project 不等于共享所有记忆。
- Agent 定义可复用，不代表其所有会话共享记忆，也不以 Agent 名称授权。
- 新外部接入默认拒绝，只有明确绑定和授权后才进入模型。
- UI 和 chat 共用后端配置服务、验证、批准、版本和审计。
- Discord 完整落地；QQ、飞书保持现有行为，适配共同能力契约，但不虚构平台能力。
- 不声称应用级工具限制是 OS 沙箱。高权限执行与受限执行明确区分。

## 产品对象与频道规则

| 对象 | 内容 |
| --- | --- |
| 连接 / Bot instance | Project、平台、凭据、平台身份、连接状态、资源目录 |
| Agent | 稳定标识、版本、指令 MD、模型、技能、工具上限、可申请的知识域 |
| 频道绑定 | Bot、频道引用、Agent 版本策略、参与者、触发方式、进一步收紧的工具和数据范围 |
| 记忆域 | 稳定数据边界、拥有者、读写授权、发布策略和版本 |

频道规则：

- 普通频道显式绑定；多选批量操作保存为明确记录，不引入任意规则表达式。
- Thread 显式绑定或禁用优先，否则继承父频道配置；继承配置不复制历史。
- 未配置、新增、已删除后重建的同名频道不接入。
- DM 单独开启、指定 Agent 和用户，默认关闭，绝不默认管理员。
- 一个 Bot 在一个位置只有一个有效 Agent；不让模型自行路由。
- 绑定使用稳定 ID；名称用于交流，改名不破坏绑定，同名必须消歧。
- 不同 Bot 独立绑定，默认忽略 Bot 消息避免循环。
- 同一频道不会因某条消息来自管理员而临时升级整个共享会话。
- 所有者可将管理助手换到独立 Bot；凭据分离不代替后端数据隔离。

## Discord 目录、能力与入站上下文

连接后即可发现可访问资源，不能要求用户先在频道发消息。

目录包含 Bot 身份、服务器 ID/名称/图标、频道 ID/名称/类型/父级、
角色 ID/名称、可查看/发送/读历史等能力、同步时间和完整性状态。

- 支持搜索、手动刷新、事件更新、重连校准、取消和限流退避。
- 区分普通频道、活动/归档/私有 Thread 的发现和操作能力；不承诺全集枚举。
- 明确区分空目录、尚未同步、部分结果、无权限、失败和不支持。
- 缓存按 Project/Bot/连接代次隔离；凭据对应身份变化后重新校验绑定。
- 显示名称可用旧缓存；授权不可把陈旧角色或平台权限当作成功。
- 名称缺失不阻止已明确绑定且授权成功的消息；授权信息缺失则暂停或拒绝。

消息传递结构化位置：Bot、服务器、频道、分类/父频道/Thread、
发送者、平台消息 ID 和元数据状态。topic、昵称、名称和消息都是外部数据，
不成为可信 system 指令。Discord 自身必须完成的应用创建、安装、权限和 intent
配置通过 App 引导及诊断；不承诺绕过平台授权。

## Internal memory：数据域授权的完整设计

### 安全目标

禁止的是“未授权内容进入该任务”，而不只是“禁止模型将它说出来”。
客服推理不能先读管理员记忆再被提示保密；过滤发生在 provider、读取和检索之前。
模型、Agent 名称、session ID、目录名称、同一 Initiative 或文件相关性都不能授予权限。

控制面管理员可以批准共享，不等于运行中的客服会话可以读取管理员数据。
Discord 发送者有私人读取权，也不等于该公共频道有权收到或保留这些数据。

### 域模型与默认矩阵

引入 Project 所有的 MemoryDomain，使用不可猜测的稳定 ID；名称和用途只是标签。
域之间没有自动继承关系，Project 内也不存在“父目录可读就全部可读”。

| 域类型 | 默认读者与用途 | 默认不可见对象 |
| --- | --- | --- |
| Project-private | 被明确授权的本地所有者/管理任务；旧内部知识归此域 | 普通外部 Agent |
| Conversation | 对应 Bot/频道或 Thread 的当前上下文代次 | 其他频道、Bot、Thread、旧代次的新任务 |
| Shared knowledge | 经所有者明确发布，授权给指定绑定的知识集合 | 未被授权的绑定 |
| Agent-private（可选显式创建） | 确实需要跨会话私有积累的用途；仍按绑定授权 | 同名 Agent 的其他未授权部署 |

不默认创建一个供所有客服频道共享的“客服 Agent 记忆”。
示例：A、B 频道可以共同读“公开帮助文档”域，但 A 的客户问题和摘要仍在 A 的
Conversation 域；管理员的部署决策仍在 Project-private 域。

Shared knowledge 也不是“互联网公开”；其授权受指定受众约束。
记录不得仅靠 public/private 布尔值或 AGENT.md frontmatter 自声明权限。

### 授权主体与执行上下文

由可信后端签发不可由请求参数伪造的有效访问上下文，包含：

- Project、绑定及其 revision、Bot/平台位置、逻辑会话及上下文代次。
- 已验证的发起者、获准的目标受众/输出位置、操作类别。
- 可读/可写域和具体资源范围、授权 revision、过期/撤销状态。
- 委派来源和可审计的父执行引用。

群会话的可读集合受固定频道受众上限约束，不随单个发送者身份扩大。
新成员不能靠加入频道获得管理员私人资源；配置者共享到频道的数据须明确承认
其面向该频道受众。平台访问变化无法确认时，敏感读取/输出不放行。

检查顺序固定为：

1. 验证 Project、执行上下文和绑定仍有效。
2. 验证该操作的能力及目标受众。
3. 验证资源所属域和当前读写授权。
4. 验证来源依赖及资源版本。
5. 在可见资源内进行相关性、排序、截断和格式化。

调用者只能选择已获授权的子集，不能提交 readDomains 来创建授权。
内部学习、恢复或管理任务使用明确服务身份，不用“没有上下文即全权”的隐式旁路。

### 资源标签、存储和旧数据

所有可进入模型的记忆资源有可信元数据：
resourceId、projectId、domainId、resourceVersion、originSession/epoch、
sourceRefs、publicationRef（如有）、创建/更新者及授权版本。

- session memory、事件、working set、wiki/decision、身份条目、摘要和学习产物都覆盖。
- 文件正文可以继续使用 Markdown；授权元数据保存在受保护的 Project 内 catalog，
  事件和持久化记录关联稳定资源 ID。不能信任模型可编辑的正文来修改 ACL。
- 复用现有 Project 持久化设施；若需要 catalog schema，则作为授权资源目录，
  不另建一套待办或完整内容数据库。
- 文件与 catalog 更新采用暂存、验证、原子发布及恢复记录；元数据缺失或不一致拒绝外部读取。
- 内容带 hash/version，外部手工改文件不能在旧“已发布”标签下悄悄替换成私有内容。
- 新资源不再使用字符替换后可能碰撞的 session 文件名作为授权身份。
- 保留旧文件；无域的旧资源默认 Project-private，不按名字、所在目录或模型猜测自动共享。
- 能可靠映射到旧会话的内容保留 provenance，但不会自动授予新外部上下文读取权。
- 新 JSONL 字段、SQLite 字段/表、旧记录读取、迁移与恢复行为一起实现。

### 所有读路径必须收口

使用同一授权核心和 scoped reader；不能只在 Discord adapter 或 UI 做过滤。

| 入口 | 必须执行的限制 |
| --- | --- |
| system prompt providers | SOUL、关键词、事件、working set、Initiative/约定、资源列表均按授权组装 |
| Session/compaction/handoff | 只装载当前可读来源和代次；旧摘要不是豁免资源 |
| `v:memory` read/list、glob/grep | 在枚举、匹配、计数、摘要生成前过滤；不泄漏隐藏路径和标题 |
| `v:sessions` 与历史搜索 | 逻辑/物理 segment、附件、摘要、引用一起验证 |
| 记忆检索/索引 | 只在已授权候选中排序；若有 embedding/reranker，同样不能接收未授权内容 |
| Project/Initiative/身份发现 | 名字、数量、状态、归属和链接也属于受控数据 |
| 文件和资源读取 | VFS 与本地路径最终映射到同一资源授权；阻止别名和原始路径旁路 |
| HTTP、UI 预览和诊断 | 管理者可看其授权数据；代表外部会话的 prompt 预览严格模拟该会话 |
| 日志、trace、导出 | 控制面独立授权，不向客服工具开放整份诊断结果 |
| 事件、跨会话消息、后台回执 | 入队和消费时校验目标域，不广播私有内容到较宽受众 |

未授权资源的“不存在”和“无权读取”对普通 Agent 使用同类不泄漏响应；
可信审计记录确切拒绝原因。正常未配置某域属于明确策略省略，
授权异常/存储损坏不能伪装成“无记忆”成功。

### 自动注入的具体改变

- `readKeywords()` 接收有效访问上下文，只枚举获准条目，不再以 general 名称授权。
- `readEvents()` 先剔除未授权来源，再区分 own/related、计算相关性和 maxRelated。
  同一 session 的旧代次事件也需验证，不能仅凭 origin 相等读取。
- “+N more”只计算可见集合，禁止透露隐藏事件数量或来源会话。
- `readWorkingSet()` 中路径也受域和代次约束，不能暴露管理目录或私有文件名。
- `SessionPromptContext` 携带服务端有效授权，provider 不拿整个 Home 任意读取。
- 上下文 provider 通过 scoped reader 返回片段及来源清单；builder 验证来源清单。
  源清单不是事后内容扫描，底层读取仍必须强制授权。
- 静态运行规则可标记为可信静态片段；Project 自定义 SOUL/约定/技能内容不是天然公开。
- 子 Agent 不因为省略某些 provider 就被认为安全；它获得父任务授权的收紧副本。

### 派生数据：防止“洗白”

读权限会随着摘要、记忆、学习和技能传播，不能在生成文本后丢失。

- 产物只可被有权读取全部受限来源的主体读取，不把多个来源的读者做并集。
- 来源跟踪覆盖本次推理实际可见的上下文，不依赖模型挑选的引用或自报“没有使用秘密”。
- 多轮任务累积已经见过的来源约束；工具获取了新敏感数据，就不能继续向更宽域写入。
- 如果一个推理读取了客服和管理数据，其摘要不能写到客服共享域。
- 日志、工具结果、decision、handoff、compaction、生成技能和索引均保留来源依赖。
- 受限会话默认只写自己的 Conversation 域，不可直接写 Project-private 或 Shared knowledge。
- 广域写入失败是显式拒绝，不能改用另一个文件工具绕过。

发布共享知识是单独的管理操作：管理员选择内容、来源、目标受众，审阅完整待发布
版本后确认，产生不可变的已批准发布记录。模型可以起草，不能自证完成脱敏，
也不能自己批准从私有域向共享域降级。

发布副本与实时派生引用区分：普通派生内容持续依赖原始授权；
已批准的固定发布版本拥有明确的独立共享许可。原始资料修改不会自动更新发布版本，
撤销发布许可则立即阻止之后使用该发布版本。UI 必须解释这个区别。

### 学习、反思与全局人格

现有 LearningRuntime.sources() 的 Project 枚举需要改为按域及兼容授权集合分批：

- 学习 worker 拿到有界来源清单、授权上下文、合法输出域，而不是整个 Project。
- 读取 `v:sessions` 的物理 segment 仍验证来源，清单内 ID 不代替授权。
- batch、ledger、cursor、重试和产物保留域及来源版本；不同域不能共用导致漏学或串域的 cursor。
- 不把管理会话和客服会话混到面向客服输出的学习批次。
- 如管理任务明确需要跨域学习，其产物仍受全部来源约束，不自动公开。
- 自动学习只能写入获准的原域/受限派生域；对共享知识、全局 SOUL、通用技能的更新生成草案。
- 学习出的技能即使不属于 memory 目录，也带相同数据约束；技能发现和加载一起过滤。
- 外部输入不能凭反思流程修改全局人格或污染其他频道共享知识。
- 私有身份记忆不因为 Discord 昵称、关联账户或同一用户自动注入公共会话。

### 缓存、撤权和上下文污染

缓存键包含 Project、绑定/授权 revision、域集合、资源版本和上下文代次，
不能仅按 Agent、query 或 session ID 缓存。目录、关键词、检索结果、摘要缓存、
prompt 缓存和持久 provider conversation 都受此约束。

- 撤权后使相关缓存和派生引用失效；本地内容保留不代表运行时仍可读。
- 活跃任务在读取、工具执行和输出提交处重新校验授权版本。
- 已装入私有内容的模型上下文不能靠新 system 指令“忘记”；取消当前生成，
  创建干净的执行代次，不重放受限历史、工具结果或旧 compaction。
- provider 复用的 conversation/cache 也必须更换，不能只清空本地字符串。
- 已读敏感来源不能写入更宽域；输出前校验目标受众与本次执行的来源约束。
- 流式输出每次发送/编辑前检查授权；撤权后停止后续块和后台完成消息。
- 已发送到 Discord 或已提交给模型 provider 的数据无法追回，审计明确记录，
  不把 abort 描述成撤销所有外部副作用。

### 不可承诺的边界

任何拥有宿主任意代码执行、原始数据库、任意文件访问或无约束 MCP 的任务，
都有可能绕过应用级记忆域。本方案对受限 Agent 禁用这些入口；
只有完成同等资源授权的工具才可加入受限工具集合。
高权限管理 Agent 明确标识为受信执行，不宣传成强多租户隔离。
远端执行尚无等价授权时拒绝相关能力，不回落到 Main 本地读取。

## Agent、工具与业务授权

Agent 管理支持创建/复制/编辑用户定义、模型、指令、技能和工具范围。
内置 Agent 只读并允许复制；内部系统 Agent 不出现在频道分配列表。
公开部署的 Agent 指令和技能自身也须经批准，不包含未授权私有内容。

有效权限受 Project、Agent 上限、频道限制、请求者、资源域及平台权限共同约束。
频道只能收紧 Agent 权限，扩权需要管理授权，新增工具默认拒绝。

统一覆盖普通工具、动态加载、invoke_tool、MCP、slash command、子 Agent、
事件、后台/计划任务、重试、跨会话操作和平台发送/读取。
管理配置能力独立授权；不将 Discord 管理角色直接映射为 Shadow 管理员。
敏感结果不得因发送者是管理员而输出到公共频道。

## Session 与配置生效

消息走 adapter → 绑定/准入 → AgentApp → SessionManager → 现有 Session。
在 slash command、静默历史记录和事件 fanout 之前完成准入，不能拒绝回答却把
未授权消息写入共享历史或交给订阅者。

保持原逻辑会话 ID；保存绑定 revision、Agent 版本、授权引用、上下文代次、
发起者和切换原因。目录名和 Agent 名不进入 ID。

| 变更 | 生效行为 |
| --- | --- |
| 展示名称 | 不重置会话 |
| 触发方式 | 下一条输入生效 |
| Agent/指令/知识/权限 | 新执行代次，旧历史保留但不自动注入 |
| 禁用/撤权 | 阻止后续工作，取消可取消工作，停止后续输出 |
| Bot 身份变化 | 旧连接代次失效，绑定重新校验 |

旧排队消息不能因配置扩权自动升级。子任务和后台任务继承有界授权；
恢复、重试、继续、延迟发送时再次校验。取消保留工具调用/结果配对和明确状态。

## UI 与 chat 的完整闭环

沿用现有 Vue 设计，不重做整个 App，也不在 Electron 实现业务逻辑。

Bot 详情包括连接、频道、变更记录；支持 server 选择、层级搜索、
已接入/未配置/异常过滤、批量绑定和诊断。ID 可复制但默认折叠。

频道编辑显示 Agent、参与者、触发方式、工具限制、Thread 继承，以及：

- 可读记忆域、可写记忆域，默认“仅当前会话”。
- 共享知识的发布者、固定版本、受众及撤销状态。
- 明确提示“同一 Agent 不共享对话记忆”。
- 有效权限来源；无法选择超过 Agent/绑定上限的域。
- Agent/权限变化将开始新上下文的影响预览。
- 不显示操作者无权枚举的记忆域名称、数量或预览。

配置检查为无副作用 dry-run：展示路由、准入、域和工具，不调用模型或平台写操作。
prompt 预览使用目标会话授权；可信管理员的原始数据管理另设清晰视角，
不能将管理员预览结果误注入客服。

chat 通过结构化能力发现资源、读取配置、生成草案、校验、确认提交。
确认绑定操作者、位置、草案 hash、revision 和有效期；模型不能自行批准。
同名资源先消歧；敏感凭据仅通过安全设置输入，不要求在群聊粘贴。
普通客服没有配置工具；获准管理会话默认不能跨 Project 管理。

异常状态包含断线、同步中/不完整、无权限、凭据失效、频道/角色/Agent/资源缺失、
限流、冲突、保存失败及已保存未应用。后两者必须明确区分。

## 服务接口、发布与审计

Project runtime 内提供资源目录、绑定解析、授权、配置草案/发布服务；
UI HTTP 和 chat tools 只做适配。围绕现有 `/api/channels/:instanceId`
扩展资源、绑定和诊断，Agent 管理使用正式接口而非 debug 写入。

- 严格 schema、请求上下文确定 Project、跨对象归属验证。
- revision 乐观锁、原子批量发布、幂等提交、失败可恢复。
- 编辑 Agent 文件使用草案/发布版本，watcher 不应用半成品。
- 外部改 MD 不能扩大授权；版本不一致时明确拒绝相关部署。
- 配置、Agent 版本和运行时有效版本一致；只有成功应用才显示已生效。
- 审计记录操作者、位置、变更摘要、域/资源引用、批准、版本和结果，不记录秘密正文。
- 授权日志只面向可信管理者；普通 Agent 不通过错误获取私有资源存在性。
- 秘密沿用私密存储，目录缓存可重建，授权和批准记录持久化。
- 订阅失效/配置应用通知复用现有 bus/SSE，不引入平行实时传输。

## 迁移与兼容

保留凭据、Bot instance、逻辑 ID、历史和旧记忆文件。迁移有版本、来源和
一次性标记，失败可恢复，不重建已删除对象。

- 旧 allowFrom/adminChats/triggerMode 生成候选，不自动扩大授权。
- 可确定等价的配置自动转换；需要猜 Agent 或授权时提示管理员确认。
- 依赖隐式 DM/adminChats 高权限的 Discord 接入暂停待确认，不继续隐式提权。
- 无授权字段的旧会话不能默认恢复为管理员。
- 无域的旧记忆归 Project-private；明确发布后才可供外部读取。
- 无来源或来源不完整的旧摘要/学习产物不自动共享。
- QQ、飞书不因 Discord 迁移改变现有信任行为，同时不宣传已有新隔离保证。

## 非目标

不自动创建 Discord 开发者应用，不重做 Discord 全部权限管理后台，
不提供 OS 沙箱，不完成远程能力隔离，不自动跨 Project 共享知识，
不承诺 QQ/飞书与 Discord 能力完全一致。未支持的安全路径显式拒绝，
而不是留下默认放行的占位实现。

## 验收：一次交付的完成条件

| 场景 | 必须验证的结果 |
| --- | --- |
| 同 Bot 双频道、双 Agent | prompt、工具、记忆范围实际不同，历史不串 |
| 多 Bot 复用 Agent | 定义复用，凭据、目录和会话独立 |
| 名称修改/同名/删除重建 | ID 绑定稳定，消歧正确，无错误继承 |
| Thread、DM、未绑定频道 | 规则明确，无隐式管理员或父历史复制 |
| 未授权角色/管理请求 | HTTP/chat/slash/普通工具均拒绝 |
| 关键词、事件、working set | 无私有标题、路径、来源、计数进入 prompt |
| 相关 Initiative/相同文件 | 相关性不能使未授权记录变为可见 |
| read/list/glob/grep/历史检索 | 直接 URI、别名、本地路径和物理 segment 无旁路 |
| SOUL/身份/约定/技能 | 公开 Agent 不隐式继承私有资料 |
| 摘要、学习、生成技能 | 私有来源不能变成客服可见产物 |
| 共享发布 | 无批准不能降级，版本固定，撤销阻止后续使用 |
| 同名 Agent、两个客户频道 | 不共享对话记忆或检索缓存 |
| 撤权与流式输出 | 停止后续读取/执行/输出，换干净上下文和 provider conversation |
| 排队、子 Agent、后台、恢复 | 不扩大父授权，不使用旧 revision 越权 |
| UI/chat 并发及重复提交 | 冲突可见，提交幂等，批量不半成功 |
| 旧记录、JSONL、SQLite | 迁移幂等且默认私有，无丢失、碰撞串域和权限复活 |
| 文件/catalog 中断与改写 | 失败可恢复，无法借旧标签读取新未批准内容 |
| 限流/缺 metadata/权限查询失败 | 明确失败或暂停，不成功式回退 |

使用不同域的唯一 canary 内容做负向断言：完整模型请求（system/history/tools）、
工具返回、搜索标题/计数、SSE、Discord 输出和面向普通 Agent 的错误均不得包含
未授权 canary；不能只检测最终回答是否泄密。授权审计的受控存在性记录单独验证。

验证使用现有 Node/tsx tests、相关后端及前端行为测试、后端/桌面/Vue 类型检查和
相关构建；针对新边界增加集成测试，不用 build 代替行为测试。
更新 channels、architecture、using-shadow、tools/automations 等当前文档时，
明确区分已实现行为与本方案。

真实 Discord 使用专用测试 server 验证双频道、角色变化、Thread、断线与撤权。
没有测试 Bot/安装权限时标记真实平台验收未完成，不能用 mock 宣称完成。

本文件仅固化计划；实际实现开始后，以上条目全部满足才可宣布完整交付。
